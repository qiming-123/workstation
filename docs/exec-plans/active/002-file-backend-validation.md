# 执行计划 002：文件后端最小集成验证

- 状态：待开始
- 前置：可用的 Windows 开发环境；可在本机使用测试数据执行
- 目标：验证 Node 认证代理与 copyparty 的最小工作链路，并确定计划 004 使用的文件后端。
- 依据：[SPEC §4.1、§8](../../../SPEC.md)、[技术方案 §1、§4](../../design-docs/tech-stack.md)

## 步骤

- [ ] 在 Windows 启动只监听回环地址的 copyparty，挂载专用测试目录。记录运行方式、进程重启步骤，以及将来接入开机自启的验证结果。
- [ ] 建立仅供本地验证的 Node + Fastify 登录和文件代理。用无会话、有效会话两组请求验证：前者无法读写测试文件，后者可经代理访问；从另一设备尝试直接访问文件后端，确认它只在本机可达。
- [ ] 在浏览器用小样本验证列表、上传、下载、新建文件夹、重命名、删除，以及图片、文本和视频预览。核对下载内容与原文件一致；使用测试目录验证中文与空格文件名。
- [ ] 重启文件后端并复测成功路径。记录认证对接方式、复现步骤、失败项和后端结论，供 003、004 和 007 使用。

## 完成标准

留有可复现的本地核验记录。copyparty 能稳定完成上述流程并满足认证边界时，按混合架构进入 004。若无法满足，记录具体失败证据，按已定回退方案推进 004；届时验证 uppy 与 tus-node-server 的适用性，其他模块按原架构推进。数 GB 文件的续传与公网吞吐由 004 和 007 验收。
