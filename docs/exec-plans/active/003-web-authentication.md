# 执行计划 003：Web 服务与单用户认证

- 状态：待开始
- 前置：计划 002 给出文件后端结论与认证边界
- 目标：在 Windows 主机提供首版 Web 入口、登录页和各模块共用的会话校验。
- 依据：[SPEC §4.4、§8](../../../SPEC.md)、[系统架构 §2–§3](../../../ARCHITECTURE.md)、[UI 设计语言](../../design-docs/ui-design-language.md)

## 步骤

- [ ] 建立 Node.js LTS + Fastify 方向的服务入口，从本地配置加载单用户凭据和签名密钥。提供不含真实值的配置示例。验证配置缺失时启动失败，并且输出不含秘密。
- [ ] 实现账号密码登录、签名 HttpOnly Cookie 会话及退出。验证正确登录、错误密码、缺失会话、过期或篡改的 Cookie、退出后刷新及重复请求。
- [ ] 建立受保护页面和功能请求共用的认证入口。以测试请求验证文件读写、设置、预设执行及 `.rdp` 下载对应的路由都经过认证；为后续功能接入保留同一校验方式。
- [ ] 按定稿 Web Demo 实现原生 HTML/JS 登录页与桌面、窄屏共用导航框架。用真实服务测试登录、刷新、会话失效和退出后的页面跳转，再记录本地启动与测试命令。

## 完成标准

Windows 主机可从配置启动真实站点；桌面和手机尺寸可用同一登录流程；应用功能服务可使用同一个认证边界。后续各计划接入实际功能后复测未登录的直达请求。
