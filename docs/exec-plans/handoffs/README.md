# handoffs — 会话交接记录

存放每次会话结束时的交接记录，供下一次会话（人或 AI）快速恢复上下文。

## 更新机制

1. **新建，不改写旧文件**：每次会话结束且有未完成事项时，新建一份记录。已存在的记录不修改，作为历史保留，用于追溯"当时以为的状态"。
2. **同日同主题追加**：同一天内多次会话接续同一主题，不新建文件，在当天那份末尾按 `## HH:MM` 分段追加。
3. **以最新一份为准，不建索引**：文件名按日期天然排序，接续工作时只读最新一份，本目录不维护 index。
4. **收尾即停**：主题完成时写最后一份简短记录（标注「已完成」），并同步把 `../active/` 中对应任务移入 `../completed/`；之后该主题不再产生记录，后续从 `completed/` 和 `../../design-docs/` 追溯。
5. **职责边界**：handoff 只记会话间交接（四段内容，见下）。方案取舍回写 `docs/design-docs/`，任务状态同步 `docs/exec-plans/`，不在此重复维护。

## 文件命名

`YYYY-MM-DD-<主题>.md`，主题为简短的连字符短语，如 `2026-11-23-资料组织.md`。

## 内容模板

```markdown
# YYYY-MM-DD <主题>

## 本次做了什么

## 进行到哪

## 下一步

## 需要注意的坑
```
